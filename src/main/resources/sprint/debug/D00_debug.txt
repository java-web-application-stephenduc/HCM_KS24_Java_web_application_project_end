### ❌ ISSUE 1: LazyInitializationException
Thông điệp:
  org.hibernate.LazyInitializationException: could not initialize proxy [...] - no Session

Nguyên nhân:
  Truy cập entity.getRelation() SAU KHI đóng Hibernate session
  (thường xảy ra khi return Entity từ Service rồi access trong Controller/Template)

Giải pháp:
  A) Dùng JOIN FETCH trong JPQL:
     @Query("SELECT ms FROM MentoringSession ms JOIN FETCH ms.student WHERE ms.id = :id")

  B) Dùng @Transactional trên method Service để session không đóng sớm

  C) KHÔNG trả Entity ra ngoài Service → map sang DTO trong Service (best practice)

  D) Dùng DTO Projection thay vì Entity với LazyLoad:
     @Query("SELECT new com.platform.dto.SessionDto(ms.id, ms.sessionDate, u.email) FROM ...")

### ❌ ISSUE 2: StackOverflowError trong JSON serialization
Thông điệp:
  StackOverflowError or Infinite recursion (StackOverflowError)

Nguyên nhân:
  Entity A có @OneToMany → Entity B, Entity B có @ManyToOne → Entity A
  Khi Jackson serialize → vòng lặp vô tận

Giải pháp:
  A) KHÔNG dùng @ResponseBody với Entity → luôn dùng DTO
  B) Nếu bắt buộc dùng Entity → thêm @JsonIgnore ở một phía:
     @JsonIgnore
     @ManyToOne
     private MentoringSession session;

### ❌ ISSUE 3: Transaction không Rollback
Thông điệp:
  Dữ liệu bị lưu một phần (ví dụ: session COMPLETED nhưng evaluation chưa có)

Nguyên nhân:
  @Transactional không hoạt động khi:
  - Method private (Spring AOP không proxy được)
  - Gọi method @Transactional từ bên trong cùng class (self-invocation)
  - Throw checked Exception (Spring chỉ rollback với RuntimeException mặc định)

Giải pháp:
  A) @Transactional chỉ dùng trên public method
  B) Không gọi this.method() → inject bean vào chính nó hoặc tách class
  C) Chỉ throw RuntimeException (hoặc config rollbackFor):
     @Transactional(rollbackFor = Exception.class)
  D) Test: kiểm tra DB sau mock exception xem có rollback chưa

### ❌ ISSUE 4: CSRF Token Missing (403 trên form POST)
Thông điệp:
  HTTP 403 Forbidden khi submit form

Nguyên nhân:
  Spring Security bật CSRF protection mặc định.
  Form không gửi CSRF token.

Giải pháp:
  Thêm vào mọi form POST trong Thymeleaf:
  <input type="hidden" th:name="${_csrf.parameterName}" th:value="${_csrf.token}">

  Hoặc dùng th:action (Thymeleaf tự inject CSRF):
  <form th:action="@{/student/booking/confirm}" method="post">  ← tự động có CSRF

### ❌ ISSUE 5: BCrypt Password không match
Thông điệp:
  Bad credentials (login thất bại dù đúng mật khẩu)

Nguyên nhân:
  Lưu password plain text hoặc hash 2 lần

Kiểm tra:
  Chạy trong DB: SELECT password_hash FROM users WHERE email = 'test@example.com';
  Kết quả phải bắt đầu bằng $2a$10$ (BCrypt format)

Test trong Java:
  BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
  System.out.println(encoder.matches("plainPassword", storedHash));  // phải true

### ❌ ISSUE 6: N+1 Query Problem
Triệu chứng:
  Trang danh sách 20 sessions → log hiện 21 query (1 list + 20 detail)

Phát hiện:
  Đếm số query trong log khi load trang → nếu = N + 1 là có vấn đề

Giải pháp:
  A) JOIN FETCH trong JPQL:
     @Query("SELECT ms FROM MentoringSession ms JOIN FETCH ms.lecturer JOIN FETCH ms.student")

  B) @EntityGraph trên Repository method:
     @EntityGraph(attributePaths = {"lecturer", "lecturer.userProfile"})
     List<MentoringSession> findByStudentId(Long studentId);

  C) Dùng DTO Projection với native query (lấy đúng cột cần thiết)

### ❌ ISSUE 7: Optimistic Lock / Race Condition (Inventory)
Triệu chứng:
  2 Admin bấm "Xác nhận xuất kho" cùng lúc → tồn kho âm

Giải pháp đã implement trong CORE-08:
  @Lock(LockModeType.PESSIMISTIC_WRITE) trên findByIdWithLock()
  → MySQL sẽ chạy SELECT ... FOR UPDATE
  → Transaction thứ 2 phải chờ transaction thứ 1 commit xong

Kiểm tra trong MySQL:
  SHOW ENGINE INNODB STATUS;  -- xem lock info

### ❌ ISSUE 8: Thymeleaf Template Not Found
Thông điệp:
  TemplateInputException: Error resolving template [student/booking]

Nguyên nhân:
  - File không tồn tại trong src/main/resources/templates/
  - Đặt sai path trong controller (phải không có dấu / đầu và không có .html)

Đúng:
  return "student/booking-form";   // → templates/student/booking-form.html

Sai:
  return "/student/booking-form";  // dấu / đầu
  return "student/booking-form.html"; // .html suffix

## PHẦN 4: MAINTENANCE CHECKLIST

### 4.1 Trước khi push code

[ ] Tắt show-sql trong application.yml (production profile)
[ ] Không có System.out.println → dùng SLF4J Logger
[ ] Không hard-code password/secret trong code (dùng env variable)
[ ] DDL-auto = validate (không phải create-drop hay update trong production)
[ ] Kiểm tra @Transactional đúng chỗ
[ ] Không có Entity leak ra Controller/Template

### 4.2 Log thay vì printStackTrace

// SAI:
try {
    service.doSomething();
} catch (Exception e) {
    e.printStackTrace();   // Không log structured, bị mất trong production
}

// ĐÚNG:
private static final Logger log = LoggerFactory.getLogger(MyClass.class);
try {
    service.doSomething();
} catch (BusinessException e) {
    log.warn("Business rule violated: {}", e.getMessage());
} catch (Exception e) {
    log.error("Unexpected error in doSomething", e);
    throw e;
}

### 4.3 Global Exception Handler

@ControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public String handleNotFound(ResourceNotFoundException ex, Model model) {
        model.addAttribute("errorMessage", ex.getMessage());
        return "error/404";
    }

    @ExceptionHandler(BusinessException.class)
    public String handleBusiness(BusinessException ex, RedirectAttributes flash,
                                  HttpServletRequest request) {
        flash.addFlashAttribute("error", ex.getMessage());
        return "redirect:" + request.getHeader("Referer");
    }

    @ExceptionHandler(AccessDeniedException.class)
    public String handleForbidden() {
        return "error/403";
    }
}
