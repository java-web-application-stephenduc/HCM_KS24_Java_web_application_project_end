# TASK — CORE-09: Hủy lịch chủ động & Giải phóng Slot (Cancellation)
# Mức độ: BẮT BUỘC | Phụ thuộc: CORE-05

## ═══════════════════════════════════════════
## MỤC TIÊU
## ═══════════════════════════════════════════
Sinh viên hủy lịch hẹn còn đang ở trạng thái PENDING, trước thời điểm
tư vấn ít nhất 24 giờ. Slot đó ngay lập tức được "unlock" để student khác đặt vào.

## ═══════════════════════════════════════════
## BUSINESS RULES
## ═══════════════════════════════════════════

Điều kiện cho phép hủy:
  1. session.status phải là PENDING (không hủy được COMPLETED, CANCELLED)
  2. Thời điểm hiện tại phải ít nhất 24h trước session_date + start_time

Sau khi hủy:
  - session.status = CANCELLED
  - Slot tự động "unlock": vì conflict check (CORE-05) đã loại bỏ status CANCELLED,
    khung giờ đó sẽ available ngay lập tức
  - Nếu đã có borrowing_record (chưa thể xảy ra vì chỉ tạo ở CORE-06),
    không cần xử lý gì thêm ở đây

## LOGIC CỤ THỂ

@Transactional
public void cancelSession(Long sessionId, String studentEmail) {

    // 1. Load session
    MentoringSession session = sessionRepo.findById(sessionId)
        .orElseThrow(() -> new ResourceNotFoundException("Session not found"));

    // 2. Kiểm tra ownership (chỉ student của session mới được hủy)
    User student = userRepo.findByEmail(studentEmail).orElseThrow();
    if (!session.getStudent().getId().equals(student.getId())) {
        throw new AccessDeniedException("Bạn không có quyền hủy lịch này");
    }

    // 3. Kiểm tra trạng thái
    if (session.getStatus() != SessionStatus.PENDING) {
        throw new BusinessException(
            "Chỉ có thể hủy lịch ở trạng thái PENDING. Trạng thái hiện tại: "
            + session.getStatus()
        );
    }

    // 4. Kiểm tra 24h trước
    LocalDateTime sessionDateTime = LocalDateTime.of(session.getSessionDate(), session.getStartTime());
    LocalDateTime cutoff = LocalDateTime.now().plusHours(24);
    if (sessionDateTime.isBefore(cutoff)) {
        throw new BusinessException(
            "Chỉ có thể hủy lịch trước ít nhất 24 giờ so với thời điểm tư vấn"
        );
    }

    // 5. Update status → CANCELLED (slot tự động unlock vì query CORE-05 exclude CANCELLED)
    session.setStatus(SessionStatus.CANCELLED);
    sessionRepo.save(session);
}

// Helper dùng trong Thymeleaf để ẩn/hiện nút Hủy:
public boolean canCancel(MentoringSession session) {
    if (session.getStatus() != SessionStatus.PENDING) return false;
    LocalDateTime sessionDT = LocalDateTime.of(session.getSessionDate(), session.getStartTime());
    return LocalDateTime.now().plusHours(24).isBefore(sessionDT);
}

## ═══════════════════════════════════════════
## LINK VỚI CORE-05 (SLOT UNLOCK TỰ ĐỘNG)
## ═══════════════════════════════════════════

Sau khi session.status = CANCELLED:
  → Query existsConflict trong CORE-05 có điều kiện:
    AND ms.status NOT IN ('CANCELLED')
  → Slot đó không còn bị đếm là conflict
  → API /available-slots sẽ trả về available=true cho slot đó
  → Không cần code thêm gì — logic tự hoạt động qua query.
